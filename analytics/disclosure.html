On the public HTTPS documentation site, a small image request to Scarf helps us understand interest in documentation pages and versions. It sends a public pixel identifier and the page origin and path. This integration omits query strings and fragments, suppresses the HTTP referrer and does not set cookies or add application runtime telemetry.

The image request also exposes normal network metadata to Scarf. Scarf may infer country and company information; this is not a verified identity or a count of installations. Caching, proxies and content blockers limit the accuracy of the results.

This integration does not send a request when your browser exposes Global Privacy Control or Do Not Track enabled. It also does not run on localhost, file URLs, HTTP or other hosts. You can block static.scarf.sh in your browser without losing access to the documentation.

For further information, see the EximeeBPMS Privacy Statement, Scarf Privacy Policy and Scarf pixel documentation.
